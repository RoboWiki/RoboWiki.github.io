# RoboWiki 信息架构决策记录（2026-10 重构）

> 这份文档记录一次「6 个 AI 视角评审 → 融合定案 → 落地」的完整过程。
> 目的不是留档，而是让下一次想改导航的人先看懂**为什么现在是这个样子**，
> 别再把已经否决过的方案重做一遍。

## 0. 一句话结论

**不推翻现有框架，做一次「导航收敛 + 任务导向首页 + 信任层曝光 + 竞赛组织层」的重构。**

页面没有变多，入口反而从 8 个收到 6 个；新增的只有 1 个页面（竞赛与实战），
而且它是「组织层」，不产生任何新数据。

## 1. 评审输入

6 份独立评审（GLM / Gemini / GPT / DeepSeek / Kimi / Claude），
各自从创业者、开源生态维护者、产品经理、初学者、竞赛参与者五个视角碰撞。

### 六份意见高度一致的结论（直接采纳）

| 共识 | 落地 |
|---|---|
| 导航不能继续平铺，同类内容要并拢 | 8 个一级入口 → 6 个（见 §2） |
| 新用户不按「部件/整机/软件」分类思考，按任务思考 | 首页加「按需求走」六个任务入口 |
| 「方法与来源」是公信力底座，必须全局可达 | 进导航「关于」组 + 页脚链接 + 各页证据条内链 |
| 竞赛群体值得独立入口，但**绝不能平行建库** | 新增 `/competitions`，只做组织层，全部回链资源库 |
| 投稿是全站动作，不是普通内容页 | 导航最右，视觉独立 |
| 不做论坛、不做灌水区 | 维持现状，互动收敛在评价 / 纠错 / 讨论区 |

### 评审之间分歧、且我们**没有**采纳的

| 提议 | 为什么不采纳 |
|---|---|
| 「整机」改名「项目库」、扩充 BOM / 复现档案 | 现阶段 21 台全是厂商整机，改名是承诺做不到的事。等真有开源项目档案再改。 |
| 复现记录（BuildRecord）作为核心新实体 | 价值共识最高，但需要「真实使用者」数据冷启动，编不出来。列入路线图（见 §5），本次不动数据模型。 |
| 团队 / 战队 / 实验室主页 | 依赖外部供稿，现在做是空页面。先在贡献者页留口径。 |
| 学习路线改成「任务制路线」（做机械臂 / 做四足） | learn.json 目前只有 4 篇文章，撑不起路线。先改文案导向，内容靠投稿。 |
| BOM 生成器 / 对比选型 / 收藏清单 | 都是 P1+，本次只做信息架构，不加交互功能。 |

## 2. 导航：8 → 6

```
旧：首页 · 机器人部件 · 机器人整机 · 机器人软件 · 使用指南 · 加工与采购 · 贡献者 · 投稿
新：首页 · 资源库▾ · 学习与竞赛▾ · 加工与采购 · 贡献者 · 关于▾ · 投稿
```

| 分组 | 包含 | 理由 |
|---|---|---|
| 资源库 | 部件 / 整机 / 软件 | 三者本质相同：可查询、可对比的数据库 |
| 学习与竞赛 | 学习路线 / 竞赛与实战 | 都是「帮我做出东西」的内容 |
| 加工与采购 | （独立保留） | 服务「制造」环节，是竞赛队最直接痛点，不并入资源库 |
| 关于 | 使用指南 / 方法与来源 / 数据来源 / 转载规范 | 信任底座全局可达，但不抢一级叙事位 |

英文区导航同步收敛，但**只放已有英文页面的入口**（不指向 404）。

## 3. 首页：加「按需求走」

在 hero 之下、「这个站在做什么」之上，插入六个任务入口：

```
我想入门机器人 → /learn/        我想找开源方案 → /robots
我想选电机/传感器 → 部件库      我要加工零件 → /suppliers
我要参加比赛 → /competitions    我想分享/纠错 → /submit
```

视觉上用虚线轻卡片，比资源入口（实线卡片）低一级——先扫到任务，再落到资源。

## 4. 竞赛与实战（/competitions）

**组织层，不是数据库。** 页面所有内容从 `data/` 实时生成：

- 赛季常用执行器速查表：按峰值扭矩取前 8，回链部件库
- 四个模块：电控 / 机械 / 项目管理 / 硬件；有内容的模块回链实战文章，缺的明说「待补」
- 加工与快速打样：回链加工与采购页
- 「这一页还缺什么」：明说兵种方案、技术报告、战队复盘需要供稿，附投稿入口

手填数字 = 必然漂移，所以整页没有一个手写型号。

## 5. 路线图（本次没做、但评审认为该做的）

| 优先级 | 事项 | 前置条件 |
|---|---|---|
| P1 | 复现记录实体（BuildRecord） | 有 ≥10 条真实复现投稿再建表 |
| P1 | 对比选型（列表页勾选 ≤3 个） | 纯前端，随时可以 |
| P2 | 整机页扩成「项目档案」（BOM / 复现 / 版本） | 有开源项目供稿 |
| P2 | 团队 / 战队主页 | 有战队认领 |
| P3 | 公开数据 API / 导出 | 数据量再上一个量级 |

## 6. 顺手修掉的（开发者视角）

- **Windows 下 `python -m pytest` 全挂**：子进程按 cp936 输出中文，测试按 UTF-8 解码炸。
  `pipeline/__main__.py` 与 `tests/test_pipeline.py` 统一给子进程注 `PYTHONIOENCODING=utf-8`。
- **首页过期文案**：「整机页的 15 台机器人」→ 去掉写死的数字（现在 21 台，由数据生成）。
- **后端在本机 Python 3.9 跑不起来**：`deps.py` 用了 3.10+ 的 `User | None` 运行时注解。
  记录在此，升级 Python ≥3.10 即可，不改源码（CI 本来就是 3.12）。

## 7. 第二轮：真实使用视角的修补（同日）

第一轮改的是「结构」，第二轮换**真实用户走一遍**，发现的都是「点下去才知道」的问题：

| 发现 | 严重度 | 处理 |
|---|---|---|
| `learn.json` 登记 4 篇文章、卡片渲染，但 `learn/` 下**没有对应页面** → 全 404 | 高 | 补写 4 篇真文章（用部件库真实数据：M3508 输出端换算、达妙扭矩密度、CAN 带宽账），并在使用指南首页加「深入读」导航 |
| 死链测试只扫 `/parts`，`/learn` 完全漏网 | 高 | 测试前缀扩到 `/learn` |
| 404 文案写死「这个型号可能还没建页」，文章/普通页面 404 时误导 | 中 | 改成通用文案，引导回首页 |
| 竞赛页 markdown 表格在 `layout:page` 自定义 div 里不渲染 | 中 | 改纯 HTML `<table>`，型号加直达链接 |
| 部件库 `battery` 品类显示「待收录」占位 | 低 | 保留——诚实标注比假装有数据强（项目既定原则） |

### 数据健康度抽查（维护者视角）

- 当时 240 个部件 `last_checked` 全是 2026-10，无过期数据（2026-10-31 复核：312 个部件，仍全部为 2026-10）
- 6 个执行器扭矩密度 >100 N·m/kg 触发 RL 红线，但都是 A 级手册真实值（QDD 关节模组正常量级），红线是「提醒复核」不是「判错」，符合设计
- 当时 149 家供应商中 112 家有质量评价、17 家无链接（社区口碑店，合理保留；现为 207 家渠道）

## 8. 第三轮：命名与定位统一 + 仓库清理（同日）

### 定位定案

> **RoboWiki = 机器人开发的开放资料底稿：可核对的参数 · 可追溯的来源 · 真实使用者的经验。**

之前三套文案在打架：首页/页脚说「公共底稿」、pyproject/config 说「部件选择社区」、
Makefile/pyproject 脚本叫「RoboSelect」。统一刷成这一句——它同时覆盖
部件/整机/软件/加工/评价五块，且「底稿」准确（供人核对、引用、续写，不是成品答案）。

### 命名定案

| 项 | 定案 | 理由 |
|---|---|---|
| 三个库 | **部件库 / 整机库 / 软件库** | 「部件」是名词，加「库」才传达「可查可对比的数据库」，三者成对 |
| 导航 | 全平铺，不折叠 | 见 §二轮：折叠藏住最高频入口 |
| `frontend/` | 改 `console/` | 名字太通用；后端本就把它挂在 `/console/`，目录名与路由一致 |
| `wiki/` | 保留 | 改 `site/` 收益小、要动 CI，不动 |
| 脚本入口 | `roboselect` → `robowiki` | pyproject 的 [project.scripts] |

### 清理掉的

| 物 | 原因 |
|---|---|
| `components/LearnHub.vue` | 死组件：学习路线首页已改成手写 markdown，无任何引用 |
| `components/_PartRating.v1.txt` `_SupplierList.old.txt` | 旧版备份，当前版本是 PartRating.vue / SupplierList.vue |
| 磁盘上的 `__pycache__` / `.pytest_cache` | 已在 .gitignore，纯本地残留 |
| README 旧导航描述 | 还停在「收敛成 6 个一级入口」，与全平铺实现不符，重写 |

### 刻意保留的（避免误删）

- `docs/README-legacy.md` + `docs/history/`：历史截图与旧稿，被调研笔记引用，属有意留档
- `tools/`（30+ 脚本）：一次性迁移工具，README 已标「会改数据谨慎跑」，是考古依据不是垃圾
- `data/_archive` `_inventory`：归档与盘点报告，下划线前缀表「非主数据」
