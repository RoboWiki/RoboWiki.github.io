# 参考项目：ZJU-HelloWorld/Wiki

- 站点：<https://zju-helloworld.github.io/Wiki/组件说明/>
- 仓库：<https://github.com/ZJU-HelloWorld/Wiki>（33★，HTML/MkDocs，183 MB，主要是图）
- 克隆方式：`git clone --depth 1 --filter=blob:none --no-checkout`（只取树，按需取 blob）
- 本地副本：`_refs/zju-wiki/`

浙大 HelloWorld 战队的机器人组件文档库。相比前三份参考（RoboParts / LeRobotDepot /
Humanoid Atlas），这份是**工程实现视角**的：讲的是「怎么把一堆电机接进同一个固件框架」，
不是「怎么在市场里挑一个」。

## 2. 它最值得抄的一件事：电机抽象

文档 1.1 节列的电机基类接口，把不同厂商的电机抹平成同一套语义：

1. 统一输入方式（原始报文 / 力矩 / 电流 / 指令）
2. **转子端 → 输出端的换算由组件负责，减速比可换**
3. 输出端编码 vs 转子端编码，两种零点标定方式分开
4. 按电机自身性能限幅，且允许用户加更严格的限制
5. 离线检测、状态访问（输出端角度/速度/力矩、转子端电流、温度）
6. 输出端编码的电机提供**微分跟踪器**算角速度

> 第 2 条和第 6 条正好对应本站在口径里反复强调的两件事：
> `armature` 要分清转子端/输出端，输出端编码的角速度噪声大。
> 战队用代码把这件事固化了，本站用字段 `inertia_basis` 固化。

它适用的电机清单（可作为「实战中被真正用过的件」的旁证）：
GM6020、M3508、M2006、M8910、宇树 A1、宇树 GO-M8010-6、
DM-J4310-2EC、DM-J8006、MF9025v2、MG6012E-i36、MG8016E-i6。

## 3. 本轮实际补充了什么

### 3.1 新增 3 个零件（目录里原本没有）

| 件 | 额定 τ | 减速比 | 质量 | 来源 |
|---|---|---|---|---|
| DJI RoboMaster GM6020 | 1.2 N·m | 直驱 | 468 g | 手册 p12 特征参数表 |
| DJI RoboMaster M3508 P19 | 3.0 N·m | 19:1 | 365 g | 手册 p12（配 C620）|
| DJI RoboMaster M2006 P36 | 1.0 N·m | 36:1 | — | 手册 p8（配 C610）|

执行器从 147 → **150**，有额定扭矩的从 40 → **43**。

### 3.2 两个口径决策（宁可留空也不混用）

**GM6020 的峰值扭矩留空。** 手册里最小的那个数是「堵转扭矩（持续堵转）0.86 N·m」，
比额定 1.2 N·m 还小 —— 因为它是**热限额**，不是电磁峰值。把它当峰值填进去，
峰值/额定比会变成 0.72，比任何真机都离谱。

**M2006 的峰值留空。** 堵转 7 N·m 只出现在同页「配 Z650 电调」那组表里，
而额定 1 N·m 是「配 C610」那组。两个电调口径混用，峰值/额定比会假成 7.0。
按 RL-02（>5 即等同堵转），这个数一进去就会污染整个分布。

### 3.3 两处来源冲突：只记录，不覆盖

| 字段 | 本目录原值（Unitree 官网） | ZJU 收录的手册 | 处理 |
|---|---|---|---|
| A1 减速比 | 6:1 | **1:9**（数据手册 p1） | 不覆盖，写进 notes |
| GO-M8010-6 重量 | 420 g | **530 g**（数据手册 p3） | 不覆盖，写进 notes |

没有第三方证据能裁决谁对，所以两个都留着，标成「来源冲突」。
静默选一个 = 替用户做决定，而这正是本站要防的事。

### 3.4 闸门改了一条规则

原来：执行器**必须有** `tau_peak_Nm`。
改成：执行器**至少要有峰值或额定之一**，只有额定则给**警告**而不是报错。

理由：只要求峰值，会把「厂商只公布额定」的件拒之门外（GM6020、M2006 正是）；
而为了过闸门编一个峰值，才是真正的错。警告文案里明说了
「跨件按峰值排序时会排最后，这是真话不是惩罚」。

## 4. 明确没采用的

- **组件库代码本身**（`HW-Components`，C++/CMake 嵌入式框架）—— 与本项目无交集
- **算法章节**（AHRS / 底盘功率限制 / 轮式底盘约束）—— 值得读，但不是选型数据
- **`领控电机材料.zip`**（63 MB）—— 若能解析出 MF9025v2 / MG6012E-i36 / MG8016E-i6
  的参数，可再补 3 个件；本轮时间不够，留作后续
- **RM 手册里的产品图** —— 那三份 PDF 是纯矢量排版，`get_images()` 返回 0，
  没有可抽的产品照，这 3 个件继续用按真实尺寸画的示意图

## 5. 复现

```bash
# 取树（不拉 183 MB 的图）
git clone --depth 1 --filter=blob:none --no-checkout \
    https://github.com/ZJU-HelloWorld/Wiki.git _refs/zju-wiki
cd _refs/zju-wiki && git config core.quotepath false

# 导出 11 份手册（必须用 cmd 的字节级重定向，PowerShell 的 > 会转成文本把 PDF 弄坏）
cmd /c "git show \"HEAD:docs/组件说明/机器人通用组件/设备应用/电机设备组件.assets/xxx.pdf\" > out.pdf"

python tools/build_zju_parts.py       # 钉死的常量 + 页码引用 → data/motors_zju.json（已归档）
python tools/build_motors.py        # 合并进 data/motors.json（已归档，现统一进 data/catalog/）
python -m pipeline validate          # 闸门
```

`tools/dump_zju_text.py` 与 `tools/dump_zju_tables.py` 是核对用的：
它们只负责把原文摆出来，**定值由人做**。用正则自动定值试过，错得离谱
（把「1:1 接口」当减速比、把整机重量当电机重量）。
