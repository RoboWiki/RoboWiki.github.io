# 账户模型与登录规则

日期：2026-11-09  
状态：当前实现口径

## 一、账号的唯一标识

| 字段 | 规则 |
|---|---|
| `handle` | **唯一用户 ID**：全局唯一、不可修改、2–24 位（a-z 0-9 - _），用于登录名、个人主页 URL、@提及。页面显示为「用户 ID：handle」。 |
| `display_name` | 昵称，可修改、不唯一；注册时可选，不填默认同 handle。 |
| `id` | 数据库自增主键，仅内部使用，不对外展示。 |
| `email` | 全局唯一；绑定后需验证才能参与写入。 |

一个 `User` 行就是一个账号；`identities` 表记录它绑定的第三方身份（`github` / `wechat_mini`）。不再用 `github_id`、`openid` 这类列，避免每接一个渠道就加一列。

## 二、三种登录方式

一个账号至少保留一种可用的登录方式；可同时绑定多种，任意一种都能进入同一账号。

1. **邮箱 / handle + 密码**（`POST /auth/login`）
2. **微信小程序**（`POST /auth/wechat/mini`，`wx.login` 的 code → openid）
3. **GitHub OAuth**（`GET /auth/github/login` → 回调 → handoff）

网页还提供**微信扫码登录**：网页拿 ticket 与小程序码 → 小程序确认 → 网页取走会话（`/auth/wechat/qr`），本质仍是微信身份。

## 三、第三方首登的账号名

微信 / GitHub 首次登录会自动建号，账号名先给临时值：`wx-<hash>`、`gh-<GitHub 登录名>`。

- 这类账号标记 `handle_provisional=true`，登录后引导到账号页设置自己的账号名；
- `PATCH /auth/handle` **只允许设置一次**，校验格式与保留字；改名后旧 JWT 失效并换发新会话；
- 邮箱注册时由用户直接填账号名，不存在临时账号名。

## 四、注册与验证（半严格）

注册只需 `handle` + 密码；邮箱与昵称都是可选项（昵称不填默认同 handle）。填写邮箱后自动发送验证邮件。同一邮箱只能绑定一个账号；重复注册会提示改用登录或找回密码。

敏感写入（评分 / 发帖 / 评论 / 投票 / 投稿 / 上传）要求**至少一种可信身份**：
邮箱已验证，或绑定了 GitHub / 微信，或站务账号。

| 账号状态 | 浏览 / 搜索 | 敏感写入 |
|---|---|---|
| 邮箱口令账号，没填邮箱 | ✅ | ❌ 403「请先验证邮箱或绑定 GitHub / 微信」 |
| 邮箱口令账号，邮箱未验证 | ✅ | ❌ 同上 |
| 邮箱口令账号，邮箱已验证 | ✅ | ✅ |
| 绑定了微信 / GitHub（无论邮箱状态） | ✅ | ✅（提供方身份已可信） |
| 站务 | ✅ | ✅ |

- 邮箱验证：账号页 / 网页账号中心粘贴邮件令牌 → `POST /auth/email/verify`。
- 微信账号在「我的 → 账号」绑定邮箱并设置密码后，即可在网页用邮箱登录同一账号。
- 验证邮件发送失败不阻断注册；用户可在账号页重发。

## 五、建号、并号与绑定

- **微信 / GitHub 首次登录**：按 `(provider, subject)` 找身份；找不到就建号（微信账号 handle 为 `wx-<hash>`，不含 openid 原文）。
- **GitHub 已验证邮箱**与现有账号邮箱一致时：按既有规则并入该账号；未验证账号只有在「没有任何第三方身份」时才可被认领，防止先占邮箱再劫持。
- **显式绑定**：
  - 微信：已登录时调用 `/auth/wechat/mini` 会把当前 openid 绑到本账号；若已属于其他账号返回 409。
  - GitHub：在小程序账号页点「去网页绑定」，网页完成 OAuth 后同一账号可用 GitHub 登录。
- **解绑**：`DELETE /auth/identities/{provider}`；若解绑后没有任何身份且未设置密码，返回 409，避免把账号锁死。
- 不做自动「邮箱 + 微信」并号：微信没有可信邮箱，必须由已登录用户显式绑定。

## 五、冲突与合并

- 同一邮箱只能绑定一个账号；重复注册只提示「登录或找回密码」，不暴露邮箱是否存在。
- 第三方身份已属于别的账号：绑定返回 409，不自动转移内容。
- GitHub 已验证邮箱与现有账号邮箱一致：按规则自动并号；其余情况不自动合并。
- **不做自动销毁**：任何情况下都不会删除另一个账号；需要合并时由站务人工处理（后续提供后台合并工具：转移帖子/评论/评分/身份后删除源账号）。
- 同一人先邮箱、后微信/ GitHub 登录且未绑定，会得到两个账号；需在账号页显式绑定。

## 六、会话与多端

- 每次登录签发 access + refresh；refresh 轮换，复用旧 refresh 撤销整条会话链。
- 账号页可查看所有设备会话（`client` 标识 web / mini / h5 / web-qr 等），单端结束或全部下线。
- 改密 / 换邮箱会吊销旧会话并重新签发当前端凭证；封禁会把 `session_epoch` 加一，旧 access 立即失效。
- `handle` 作为唯一用户 ID 贯穿网页、小程序、GitHub、微信与导出数据。

## 七、找回密码

1. `POST /auth/password/forgot`：提交邮箱，统一返回 202（不暴露邮箱是否存在）。
2. 邮件里是**一次性令牌**（不是链接）。
3. `POST /auth/password/reset`：令牌 + 新密码；成功后旧密码失效。
4. 重置后到登录页用邮箱或 handle 重新登录。

## 参考：主流社区的做法

| 产品 | 账号名 | 第三方首登 | 冲突/合并 |
|---|---|---|---|
| Discourse | 注册必填 username，可改但有冷却与历史 | OAuth 自动建议 username | 后台 **Merge Users**，人工合并 |
| Flarum | 注册必填 username | OAuth 扩展按已验证邮箱关联 | 合并靠后台扩展，不自动删号 |
| NodeBB | 注册必填 username（有长度校验） | SSO 自动生成 | 合并靠后台插件 |
| Homeland / paopao-ce | login/username 与 nickname 分离 | 第三方首登自动建号 | 资料可改，合并靠后台 |

共通点：**自动关联只认提供方已验证的邮箱；冲突不销毁账号；合并是人工/后台操作。**

## 八、前端入口

| 端 | 登录 | 注册 | 找回密码 | 邮箱验证 | 绑定身份 |
|---|---|---|---|---|---|
| 网页 `/login.html` | 密码 / GitHub / 微信扫码 | 邮箱建议填写 | ✅ 面板 | 账号中心「安全」 | GitHub、微信（扫码即登录） |
| 小程序 `pages/login` | 微信一键 / 账号密码 | 邮箱建议填写，自动发验证邮件 | ✅ 邮箱 + 令牌 | 「我的 → 账号」 | 微信（本页）、GitHub（网页 OAuth） |
