# 电控

::: warning 这一模块还是空的
不是忘了写，是**没有可核的一手材料**。电控里最值钱的是「别人踩过的坑」——
同样的 CAN 负载，为什么有的队稳定、有的队掉线；同样的状态机，为什么赛场上会卡死。
这些只能来自真打过比赛的人，编不出来，也不该由我们编。
:::

## 该有什么

按一支队伍的调试顺序，这一模块应该长这样：

| 环节 | 要回答的问题 |
|---|---|
| **主控与实时性** | 控制周期定多少、为什么是这个数；RTOS 还是裸机；中断里能做什么不能做什么 |
| **总线与频率预算** | CAN 波特率与关节数怎么算、什么时候必须拆总线、丢帧怎么定位 |
| **驱动器配置** | 电流环/速度环/位置环怎么切、限幅放在哪一层、上电时序与抱闸逻辑 |
| **状态估计** | IMU 装在什么位置、零偏怎么标、和轮速/关节反馈怎么融合 |
| **整车状态机** | 上电 → 自检 → 站立 → 行走 → 保护 → 急停，每条的进入与退出条件 |
| **赛场调试** | 日志怎么记、回放怎么用、现场改参数怎么不烧板子 |

## 想供稿？

如果你打过比赛，这几条比任何通用教程都值钱：

- 一个具体故障 → 排查路径 → 最后发现是哪里（**要有现象和最终原因**）
- 一份能跑的状态机或总线配置，附上为什么这么定参数
- 赛场上的应急处理：掉线、冒烟、失控分别怎么处置

投稿入口：[投一篇电控实战](https://github.com/RoboWiki/RoboWiki.github.io/issues/new?template=article.yml&labels=article) 或看 [全部投稿方式](/submit)。

> 机械模块已经有四篇一手材料，可以先看那边的「顺序建议」——
> 电控和机械的接口（电机、编码器、限位）是在结构设计阶段就要定的。
