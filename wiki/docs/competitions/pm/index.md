# 项目管理

比赛里「技术都对、还是输」通常不是技术问题：**进度没排、接口没定、评审没做，最后一周全在返工**。
这一模块放的是从 0 到 1 做一台整机的**流程样板**，不是鸡汤式的时间管理。

## 现有材料

| 材料 | 讲什么 | 什么时候读 |
|---|---|---|
| [RP1 白皮书](/competitions/pm/rp1-whitepaper) | 一个模块化人形平台从**设计约束 → 本体设计 → 通信架构 → 训练与部署**的完整工程流程（60 页） | 立项阶段。想知道「一台整机是怎么被拆成可并行的工作包」 |

::: tip 这份白皮书为什么归到项目管理
它当然讲技术，但真正的价值在于**先后顺序和取舍理由**：
先用执行器与可维护性约束反推本体（髋关节轴线分离、踝关节并联），
再定通信（分段式 CAN-FD + 统一关节指令接口），最后才是训练与部署。
这套顺序本身就是一份项目计划 —— 照着它排里程碑，比拍脑袋排期靠谱。
:::

## 该补什么

| 环节 | 要回答的问题 |
|---|---|
| **里程碑与冻结点** | 什么时候冻结结构、什么时候冻结电路、冻结后再改要付什么代价 |
| **接口先行** | 机械↔电控↔硬件的接口表（尺寸、力矩、供电、通信、时序），谁定、什么时候定死 |
| **评审机制** | 设计评审看什么、谁有否决权、什么情况必须重做而不是打补丁 |
| **并行与依赖** | 哪些工作包可以并行、哪些必须串行（结构等电机参数、电路等结构尺寸） |
| **赛季节奏** | 备赛期 / 比赛周 / 现场抢修三段时间的管理方式完全不同 |
| **复盘** | 输了要能定位到「哪个决策错了」，而不是「运气不好」 |

## 想供稿？

最有价值的三类：

- **一次真实的排期**：从立项到上场的时间线，中间哪几个节点延了、为什么
- **一次接口事故**：机械和电控对不上，最后是谁的错、怎么补救
- **一份评审清单**：你们队设计评审时逐条看什么
