# 硬件

硬件组在 RM 里管的是「电怎么进来、怎么稳住、怎么送到执行器」：电源树、驱动、接口、PCB、焊接与调试。
这一模块现有四篇材料，都是可照做的训练路径。

## 现有材料

| 材料 | 讲什么 | 什么时候看 |
|---|---|---|
| [RoboMaster 硬件组做什么](/competitions/hardware/hw-what-we-do) | 职责边界：升降压电源模块、开发板与外设（IMU / USART / CAN / USB / S.BUS）、舵机与电机驱动 | **决定要不要进硬件组之前**，一页看清这活儿是什么 |
| [硬件组入门与训练安排（重山战队 2026）](/competitions/hardware/hw-training-2026) | 电路基础 → Buck 电源 → 超级电容（含开源超电板案例）→ 四开关 Buck-Boost → PCB（嘉立创 EDA）→ 工具 → 焊接 → 训练题目与检查清单 | 入队第一个月，按顺序照着做 |

可以直接当考核标准用。联系群号与房间号已隐去。

## 该补什么

| 环节 | 要回答的问题 |
|---|---|
| **电源树** | 几路电压、谁给谁供电、峰值电流怎么估、上下电时序为什么这个顺序 |
| **电机驱动与保护** | 母线电容怎么选、续流与制动怎么处理、过流/过温保护放在硬件还是软件 |
| **传感器接口** | 编码器/CAN/SPI 的电气隔离要不要、长线怎么抗干扰、地怎么分 |
| **PCB 布局** | 大电流回路面积、铺铜与过孔、功率地与信号地的汇合点 |
| **故障排查** | 上电不启动、通信偶发丢包、复位重启、烧管 —— 各自的**第一步量哪里** |

## 想供稿？

最有用的不是「设计规范」，是**故障档案**：

```
现象：……（什么时候出现、多大概率）
误判：我们一开始以为是……
定位：最后量到 ……（哪个点 / 哪个器件）
原因：……
修法：……（改了什么，验证方式）
```

一条这样的记录，比十页通用建议有用。
