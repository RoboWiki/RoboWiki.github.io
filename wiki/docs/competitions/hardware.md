# 硬件

::: warning 这一模块还是空的
赛场上的「玄学问题」八成出在电源与接地 —— 但这类知识必须带具体案例才有价值：
什么现象、怎么复现、最后量到哪个点不对。没有案例就写成「注意电源完整性」，
那是废话。所以先空着。
:::

## 该有什么

| 环节 | 要回答的问题 |
|---|---|
| **电源树** | 几路电压、谁给谁供电、峰值电流怎么估、上下电时序为什么这个顺序 |
| **电机驱动与保护** | 母线电容怎么选、续流与制动怎么处理、过流/过温保护放在硬件还是软件 |
| **传感器接口** | 编码器/CAN/SPI 的电气隔离要不要、长线怎么抗干扰、地怎么分 |
| **PCB 布局** | 大电流回路面积、铺铜与过孔、功率地与信号地的汇合点 |
| **故障排查** | 上电不启动、通信偶发丢包、复位重启、烧管 —— 各自的**第一步量哪里** |
| **赛场维护** | 备件清单、易损件、线束应力与固定、故障件的快速替换 |

## 想供稿？

最有用的不是「设计规范」，是**故障档案**：

```
现象：……（什么时候出现、多大概率）
误判：我们一开始以为是……
定位：最后量到 ……（哪个点/哪个器件）
原因：……
修法：……（改了什么，验证方式）
```

一条这样的记录，比十页通用建议有用。
