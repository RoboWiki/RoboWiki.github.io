# 交互式检索

这一页**没有一个 API 请求**：目录在构建时导出成 `catalog.json`，
搜索 / 筛选 / 排序 / 对比全部在浏览器里算。

<PartExplorer />

## 为什么静态站能做这件事

「选型台要不要服务器」这个问题的答案取决于**数据动不动**：

| | 静态站（VitePress） | 需要后端（FastAPI） |
|---|---|---|
| 读目录、排序、筛选、搜索 | ✅ 构建时导出 + 客户端计算 | 不必 |
| 每个型号有独立 URL、可分享 | ✅ 构建时生成页面 | 要 SSR 或预渲染 |
| 首屏之后交互零延迟 | ✅ 一次取完 134 KB | 每次请求走网络 |
| 要被搜索引擎收录 | ✅ | 需要额外处理 |
| 登录、发帖、投票 | ❌ | ✅ |
| 后台改数、改动留痕 | ❌ | ✅ |
| MCP / 给 Agent 调用 | 可以（同一份 JSON） | ✅ |

也就是说：**这个项目的 90% 是只读的**（191 个零件、参数、口径），
那部分放静态站更划算；只有「写」的那一小块需要服务器。
