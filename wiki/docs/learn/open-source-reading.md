# 开源机器人项目怎么读：从 URDF 到训练配置

一个机器人开源项目「能不能用」，看四样东西就够了：**URDF、SDK、训练配置、标定脚本**。四样齐的项目，通常当天能跑起来；缺两样的，通常要花两周补。

## 一、URDF：比官网参数表更硬的一手数据

官网参数表是**宣传口径**，URDF 是**工程口径**。同一台机器狗：

| 数据 | 官网 | URDF |
|---|---|---|
| 自由度 | 「12 自由度」 | 12 个 joint，每个带 `limit`、`axis` 与 `origin` |
| 尺寸 | 「约 0.7 × 0.3 × 0.4 m」 | 每根连杆的 `length` 与 `origin xyz` |
| 质量分布 | 「约 15 kg」 | 每个 link 的 `mass` 与 `inertia` 张量 |

所以判断「这台机器人到底是什么」时，**先看 URDF**。本站整机页把 `urdf_urls` 与 `repo_urls` 单列出来，就是这个原因：链接指向官方 `_description` 仓库的，才算能进仿真。

怎么快速验一份 URDF：

```bash
# 1. 关节数与类型
grep -c "<joint" robot.urdf

# 2. 有没有 inertial（没有就跑不了动力学）
grep -c "<inertial" robot.urdf

# 3. 有没有 mesh 引用（缺 mesh 只能看线框）
grep -o 'filename="[^"]*"' robot.urdf | head
```

三个数对得上（joint 数 ≈ 1 + link 数、inertial 数 = link 数、mesh 都能下载），这份 URDF 就是可信的。

## 二、SDK：能不能真的发指令

看三件事：

1. **有没有 example**：只有 API 文档没有可运行示例的，基本等于没有
2. **控制模式覆盖**：位置 / 速度 / 力矩 / 混合，少一个就限死一类算法
3. **反馈频率**：SDK 能不能 500 Hz 以上拿到状态？拿不到就做不了高动态控制

以宇树的 `unitree_sdk2` 为例：example 齐全、支持低级控制、有 C++ 与 Python 绑定，这是「能拿来做事」的形态。

## 三、训练配置：能不能复现

强化学习项目最容易「只有结果没有过程」。看仓库里有没有：

- 训练用的 YAML（环境参数、奖励权重、课程学习曲线）
- **checkpoint**（有权重才能验证作者的结论）
- 随机化范围（domain randomization 的上下界写没写）

缺 checkpoint 的项目，你只能重训；缺奖励权重的项目，你连重训都复现不了。

## 四、标定脚本：决定真机能不能落地

仿真到真机的最后一公里几乎全在标定上：

| 要标的东西 | 有没有脚本 |
|---|---|
| 关节零位 | 有 → 装机当天能走；没有 → 靠肉眼对，走起来是歪的 |
| IMU 安装误差 | 有 → 姿态可信；没有 → 步态往一边偏 |
| 电机方向与符号 | 有 → 不会出现「一条腿反着转」 |
| 足端几何（腿长、轮距） | 有 → 里程计可用 |

## 五、读项目的顺序

```
README（看它声称能做到什么）
  → URDF（看它物理上是什么）
  → example（看指令怎么发）
  → 训练配置（看作者的结论能不能验）
  → 标定脚本（看真机能不能落地）
  → issues（看别人卡在哪）
```

最后一步经常被跳过，但它信息量最大：**issues 里重复出现的问题，就是你要付的学费**。

## 六、判断清单

给一个项目打分（每项 1 分，≥ 4 分值得投入时间）：

- [ ] URDF 或 MJCF 齐全，inertial 与 mesh 都在
- [ ] SDK 有可运行 example，支持力矩级控制
- [ ] 有训练配置 + checkpoint
- [ ] 有标定脚本（零位、IMU、方向）
- [ ] 最近 6 个月有提交
- [ ] issues 有人回

## 七、去哪里找这些项目

本站[机器人整机](/robots)里的 15 台机器人都标了 URDF / 仓库链接，其中开源程度高的几台可以直接拿来做对照：
