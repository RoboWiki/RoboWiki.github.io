# 开源机器人项目怎么读：从 URDF 到训练配置

GitHub 上机器人项目很多，但「star 多」和「我能照着做出来」之间隔着很远。判断一个开源项目能不能复现，不用读完整个仓库——看四样东西就够了。

## 四样东西，按顺序看

### 1. URDF / 模型文件：有没有、对不对

URDF（或 MJCF）是机器人的「骨架描述」。一个项目连 URDF 都没有，基本只能当论文看，没法进仿真。

有了还要看质量：

- 关节的 `limit`（限位）、`dynamics`（惯量）填了没有，还是全是默认值
- `mesh` 文件在不在仓库里，还是只写了本地路径
- 连杆质量分布合不合理（全写 1 kg 的，是占位符）

> 本站整机页每台都标了 URDF 链接，且只列**有公开仓库**的——链接打不开的就不写。

### 2. 训练配置： reward 怎么设计的

如果是学习类项目，找 `config` / `cfg` / `reward` 相关文件。能复现的项目，奖励函数的每一项都写得出来；只能跑 demo 的项目，往往只有一个跑通的 checkpoint，没有训练代码。

重点看：**有没有从零训练的脚本**，还是只给了「加载预训练模型跑推理」。前者能复现，后者只能演示。

### 3. 部署代码：sim-to-real 怎么过的

仿真里跑得好，不代表真机能动。看仓库里有没有：

- 真机部署的入口（`deploy` / `real` / `hardware` 目录）
- 仿真到真机的接口层（怎么读编码器、怎么下发力矩）
- 通信部分用的什么协议（CAN / EtherCAT / 串口）

缺了部署层，说明作者可能只在仿真里验证过。

### 4. 维护状态：最后一次提交是什么时候

一个三年没更新、依赖 ROS Noetic 的项目，今天大概率跑不起来。看：

- 最近一次 commit 的时间
- issue 区有没有人在维护、有没有人问「跑不通」
- 依赖的版本是不是已经淘汰（Python 2、CUDA 9 这类）

## 一张判断清单

对着仓库打勾，全中的才值得投入时间：

```
□ 有 URDF/MJCF，且惯量/限位不是占位符
□ 有从零训练的脚本（不只是预训练权重）
□ 有真机部署层，写了通信协议
□ 最近一年内有维护活动
□ README 写了硬件清单和依赖版本
```

中 4 条以上：可以复现。中 2–3 条：能借一部分（比如只要 URDF）。中 0–1 条：当论文读，别指望跑起来。
