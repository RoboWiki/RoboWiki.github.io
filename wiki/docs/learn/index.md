# 怎么用这个网站

这不是教程，是**使用说明**。看完你应该知道：哪个数字能信、为什么有的格子是「—」、
以及「我想做 XX，该去哪一页」。

---

## 一、先认识这里的三类内容

| 板块 | 回答什么问题 | 什么时候去 |
|---|---|---|
| **机器人部件** | 「这个关节电机 / 芯片 / 传感器，参数到底是多少，多少钱，谁用过」 | 你在选型、做 BOM、或者想核对某个数 |
| **机器人整机** | 「这台机器是什么方案，开源世界里有谁在它上面做过事」 | 你在定方案、找参考实现、评估「能不能照着做」 |
| **机器人软件** | 「仿真、训练、部署这条链上，每一层该用哪个工具，许可能不能商用」 | 你要搭环境、换后端、或者判断某个框架能不能进产品 |

三个板块是**并列**的，不是目录关系：部件库不包含整机，整机里也不会重复部件的参数。

---

## 二、部件页：先看「来源等级」，再看数字

每个部件页左边是参数，右边是评分。**左边每一个数字都带来源**：

| 等级 | 含义 | 你该怎么用 |
|---|---|---|
| **A** | 逐项核对过厂商手册 / 官方文档，每个字段都能指回一手来源 | 可以直接拿去做计算 |
| **B** | 采自商品页或第三方整理，未逐项核对 | 可以用，但关键数字（扭矩、电流、精度）自己复核一遍 |
| **C** | 转述、仅作线索 | 只当「有这个东西」的提示，别引用数值 |

页面上「来源 B」这样的标签就是它。**B 级不会做视觉强调**——不是我们藏，是它本来就没那么硬。

### 为什么很多格子写着「—」

因为厂商没公布，或者公布了但我们没核到。这里的规则是**缺就写 `null`，不省略字段**：

- 省略字段会让人以为「这项没有」
- 而 `null` 明确表示「厂商没公布」

所以你看到「—」有两个可能：厂商没给，或者我们还没核到。**没有第三种可能**（比如「约」「大概」这种糊过去的写法——这里不用）。

### 几个容易踩的口径

| 你会遇到的坑 | 这里的处理 |
|---|---|
| 扭矩是电机端还是减速箱输出端？ | **一律给输出端**（含减速箱）。原始值留在 `specs.torque_raw` |
| 峰值扭矩能连续跑吗？ | 不能。峰值有持续时间与初始温度条件，页面会写 |
| 额定电压还是范围？ | 分开两个字段，不合并 |
| 价格含不含税、是不是活动价？ | 只收国内含税挂牌价，来源与采集日期写进备注；活动价标注「可能随活动变化」 |

## 三、评分怎么读（以及为什么样本少时会直说）

每条评价**必填三项**：总分（1–5）、你用过这个件吗、一句话理由。分维度（性价比 / 做工 / 文档 / 参数可信度…）是选填，按品类不同。

三条规则值得知道：

1. **一人一件一票**：唯一键是「你的账号 + 部件 id」。改主意就编辑原来那条 issue，不会算两票。
2. **样本 < 3 条标「样本不足」**：1 条 5 分和 20 条 5 分不是一个确定程度，页面不把它们当一回事。
3. **装过机和没装过机分开算**：只有「装过机」的评价进 `own_hardware_avg`。

评分不是「谁更专业」加权——那会变成黑箱。只用「装过 / 没装过」这个可核对的区分。

## 四、列表页怎么筛

三个列表页共用一套交互：

- **搜索框**：型号、厂商、类型都能搜
- **分面（chips）**：点一下筛，再点一下取消。部件页按品类分面，整机页按构型 + **有无开源生态**，软件页按层
- **排序**：右上角下拉。部件可以按任意参数列排；整机有「按开源生态」；软件有「按许可宽松度」

---

## 五、整机页：为什么强调「开源生态」

一台机器的参数表只能告诉你它多大、多重、几自由度。但真正决定「我能不能做出来」的是：

**这台机器在开源世界里有多少现成工程可以借。**

所以整机页每张卡片都有一行「开源生态 N 项」，点进详情页会按环节拆开：

```
官方项目 · 官方描述/资产 · 官方 SDK · 仿真 · 训练 · 部署 · 导航 · 控制/MPC · 工具/资料
```

**只列有公开 GitHub 仓库的项目**——本地工程和「通用 API 参考」不上页面，因为读者点不动，
也说明不了这台机器。没有链接的机型就写「—」，不凑数。

---

## 六、软件页：许可和版本比功能重要

选软件时最容易踩的不是「功能不够」，而是：

- **许可不能商用**（GPL 进产品要开源）
- **版本对不上文档**（教程写 2.x，你装的是 1.x）
- **硬件门槛**（Isaac 系要 NVIDIA 卡，MuJoCo 单机 CPU 就行）

所以每张卡片上**许可、版本、语言**都直接标出来：

- 宽松（Apache / MIT / BSD）→ 品牌色
- copyleft（GPL / MPL）→ 琥珀色
- **未核对 → 虚线灰**，因为「读不到」和「没有」是两件事，我们不猜

页面底部还有一张「怎么选（按约束倒推）」的表——按你手上的机器和卡，不按名气。

---

## 七、这些数据是谁核的、错了找谁

- 每个部件页底部写着**来源、收录方式、核对日期**
- **贡献者页**写清每个人具体做了什么（不从 git log 生成——机器只会数 commit，说不出谁核过哪本手册）
- 发现错误：部件页有「纠错」入口（GitHub issue 表单），也可以直接在讨论区说

数据出错时，我们希望能找到具体的人，而不是一句「欢迎指正」。

---

## 八、你真要开始做东西的话

1. **定方案**：整机页 → 看构型与生态，挑一台「有现成训练/部署工程」的
2. **列 BOM**：部件页 → 按品类筛，A 级直接算，B 级自己复核关键项
3. **搭环境**：软件页 → 按「怎么选」表定引擎与训练框架，先看许可
4. **写代码之前**：去整机详情页看它的官方项目，别从零搭

这里不卖零件、不收佣金、没有推荐位——所以排序里不会有人为的「优先展示」。
