# 第一次做整机选型：先算什么，后算什么

选型最容易犯的错是「先看中一个电机，再围着它凑一台机器」。顺序反了。正确的方向是**从任务往回倒推**：任务决定构型，构型决定自由度，自由度决定关节扭矩，扭矩定了才轮到看具体型号。

这篇给一条可复现的倒推链，每一步都附算法。

## 第 0 步：把任务写成一句话

在打开任何参数表之前，先写清楚：

> 这台机器要在【什么地面】上，以【多快】，驮【多重】，连续干【多久】。

「做一台四足」不是任务，「在瓷砖地上以 1 m/s 走、驮 2 kg 传感器、连续 30 分钟」才是。没有这句话，后面的每一步都没有判据。

## 第 1 步：定构型与自由度

去[整机库](/robots)看现成方案，按构型筛。自由度不是越多越好——每多一个关节，多一份成本、重量、故障点和控制难度。

| 任务 | 常见构型 | 典型自由度 |
|---|---|---|
| 平地巡检、教学 | 四足 | 12（3/腿）|
| 要越障、上下楼 | 四足 / 轮足 | 12–16 |
| 精细操作 | 机械臂 | 6–7 |
| 人形研究 | 双足 + 双臂 | 20+ |

> 整机页每台都标了自由度和「开源生态 N 项」。第一台机器强烈建议挑**生态完整**的——有现成 URDF 和训练工程，比省几千块钱值钱得多。

## 第 2 步：算关节扭矩（最关键的一步）

构型定了，就可以算每个关节需要多大扭矩。静态站立时，单关节的保持扭矩近似：

```
tau ≈ m × g × L / n
  m = 整机质量（kg）
  L = 该关节到足端的距离（m）
  n = 同时承重的腿数
```

举例：20 kg 四足、腿长 0.4 m、两腿支撑相 → 髋部关节 ≈ 20×9.81×0.4/2 ≈ **39 N·m**。再乘 1.5–2 的安全系数，得到你该选的**额定**扭矩 ≈ 60–80 N·m。

> 用[关节电机库](/catalog?category=actuator)按额定扭矩筛，落在 60–80 N·m 区间的，才是你的候选。别拿峰值扭矩去对——峰值只够撑瞬间。

## 第 3 步：定算力

控制环频率决定你要多强的下位机，感知需求决定上位机：

| 需求 | 算力配置 |
|---|---|
| 纯位置/力矩控制（1 kHz） | 一块 MCU 下位机（见[下位机](/catalog?category=controller_low)）即可 |
| 跑状态估计 + MPC | 需要带 FPU 的高性能 MCU 或小型上位机 |
| 视觉 / 学习类策略 | 需要带 GPU/NPU 的[上位机](/catalog?category=controller_high)（注意 Isaac 系要 NVIDIA 卡） |

先想清楚「我的算法在哪一环跑」，再选板子。反过来「先买块 Jetson 再说」常常是用不上。

## 第 4 步：配传感器

按任务的最小集合配，不要堆：

- 姿态：一颗 [IMU](/catalog?category=imu) 几乎是底线
- 测距/避障：深度相机或[激光雷达](/catalog?category=lidar)二选一起步
- 足端触地：力/触觉传感器（看「其余模块」）

每加一个传感器，问自己：「没有它，任务那句话还成立吗？」成立就先不加。

## 第 5 步：列 BOM，核关键项

到这一步才去比具体型号。把候选件列成 BOM，**A 级数据直接用于计算，B 级的关键项（扭矩、电流、精度）回原厂页面复核一遍**。

最后检查三件最容易漏的事：

1. **电压平台一致**：电机额定电压、电池、电调要配得上
2. **通信总线带宽够**：见[电控链路怎么搭](/learn/control-chain)
3. **机械接口对得上**：法兰、轴径、出线方向——参数表看不出来的，去整机详情页找实物图
