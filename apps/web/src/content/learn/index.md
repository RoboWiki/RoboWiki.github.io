这个站是一个**可核对的部件库 / 方案库 / 设备库 / 采购库**，另有一个按需求推导 BOM 的试验版选型台。核心回答四个问题：

- 这套机器人要买什么、怎么配？→ [选型台](/selector.html)
- 这个型号的参数到底是多少、多少钱，谁真用过？→ [部件库](/catalog.html)
- 这套方案能不能照着复现？→ [方案库 · 整机](/robots.html)
- 仿真、训练、部署各用哪个软件，许可能不能商用？→ [软件库](/software.html)

它不是课程，也不卖零件：不教你怎么写第一行代码，也不替你下单。**它最大的用处是让你少买错一个件** ——
一个买错的关节电机，比读十篇文章贵得多。用过的人会在部件页下留下具体实测与评价，选型前先看那些，而不是只看均分。

30 秒确认规模：351 个部件、69 台设备、42 台整机、41 项材料与工艺、22 个软件、234 家渠道。

## 机器人由哪几块组成

先有地图，再挑零件。一台能动的机器人基本就是这七层，右边是本站对应的入口：

| 组成 | 干什么 | 第一次做要注意 | 本站入口 |
|---|---|---|---|
| 结构件与传动 | 机身、腿、同步带、减速箱 | 3D 打印能覆盖小尺寸件；承力的件才上 CNC | [采购库](/suppliers.html) 找加工 |
| 执行器（关节） | 把电变成扭矩 | 先分清「电机」和「集成驱动的关节模组」 | [关节电机 90](/catalog.html?category=actuator) · [舵机 7](/catalog.html?category=servo) |
| 驱动与总线 | 把指令变成电流，把十几个关节串起来 | 12 个关节挂一路经典 CAN，1 kHz 下带宽不够 | [电调 3](/catalog.html?category=esc) · [电控链路怎么搭](/learn/control-chain.html) |
| 主控与算力 | 跑控制环、跑策略、跑视觉 | 先想清算力跑在哪一环，「先买块 Jetson」常常用不上 | [下位机 9](/catalog.html?category=controller_low) · [上位机 17](/catalog.html?category=controller_high) |
| 传感器 | 知道自己在哪、踩没踩到地 | 一项任务加一个就够，别堆 | [IMU 17](/catalog.html?category=imu) · [深度相机 15](/catalog.html?category=camera) · [激光雷达 13](/catalog.html?category=lidar) |
| 电源与连接 | 供电、接线、别烧 | 全机电压平台要一致；连接器载流看标称电流 | [电池 8](/catalog.html?category=battery) · [连接器 24](/catalog.html?category=connector) |
| 软件 | 仿真、训练、部署 | 先看许可（GPL 进产品要开源），再看硬件门槛 | [软件库](/software.html) |

> 这里没有独立的「结构件库」：结构件的可信参数依赖具体 BOM，本站宁可空着，也不拿典型值充数。

## 第一次来，按顺序做这五件事

这里不排课程表（那种「30 天入门」多半是编的）。下面五个动作每一件都有明确产出，加起来约 50 分钟。

| # | 做什么 | 打开 | 你会得到 | 用时 |
|---|---|---|---|---|
| 1 | 认 14 个词 | 下面那张**术语表** | 一张电机参数表能看懂七成 | 5 分钟 |
| 2 | 学会读六个数字 | [关节电机参数怎么读](/learn/motor-specs.html) | 知道「峰值 ≠ 额定」「电机端 ≠ 输出端」各差几倍 | 12 分钟 |
| 3 | 把任务写成一句话，倒推扭矩 | [第一次做整机选型](/learn/selection-order.html) | 一个能拿去筛件的扭矩区间（N·m） | 15 分钟 |
| 4 | 去部件库筛一个有来源的件 | [部件库 · 关节电机](/catalog.html?category=actuator) | 1 个候选型号 + 它每个数字的出处 | 10 分钟 |
| 5 | 找一台能进仿真的整机 | [整机库](/robots.html)（筛「有开源生态」） | 1 台有 URDF 或训练工程的参考机型 | 10 分钟 |

走完第 5 步，你手上应该有一句话（任务）、一个扭矩区间、一个候选型号、一台参考机型 —— 这够开始搭第一台东西了。
接下来选软件去 [软件库](/software.html)，要打比赛去 [实战资料](/competitions.html)。

## 术语表：最容易被劝退的 14 个词

| 词 | 一句话解释 | 在哪会看到 |
|---|---|---|
| 执行器 / 关节电机 | 让关节转起来的那一坨（电机 + 减速箱 ± 驱动器） | 部件库分类 |
| 输出端扭矩 | 减速箱**之后**能拧多大劲。本站一律用这个口径 | 所有关节电机参数 |
| 额定 vs 峰值 | 额定能连续跑；峰值只能瞬间爆发，且必须给持续时间与初始温度 | 参数表前两行 |
| 减速比 | 电机转 N 圈、输出转 1 圈；扭矩大约 ×N，转速 ÷N | 关节电机 |
| 扭矩密度 | 峰值扭矩 ÷ 质量（N·m/kg），超过 120 就要回头复核 | 选型指标 |
| 自由度（DOF） | 能独立动的关节数：四足常见 12（每腿 3） | 整机页 |
| 上位机 / 下位机 | 上位机跑视觉与策略；下位机跑 1 kHz 的控制环 | 部件库分类 |
| CAN / CAN FD | 关节最常用的总线：经典 CAN 1 Mbps，CAN FD 可到 5 Mbps | 通信参数 |
| IMU | 陀螺仪 + 加速度计，知道姿态 —— 几乎是底线传感器 | 传感器分类 |
| URDF | 机器人的「骨架文件」，没有它进不了仿真 | 整机页 |
| BOM | 物料清单：要买什么、几个、单价多少 | 选型文章 |
| 来源 / 核对日期 | 每个数字尽量指回厂商手册、官方数据表或商品页，并记录最近核对时间；没出处的只作线索 | 每个部件页 |
| 「—」/ null | 厂商没公布，或者我们没核到。**不是「这项没有」** | 参数表 |
| 样本不足 | 打分的人少于 3 个，页面不给你一个看起来很确定的均分 | 评分区 |

## 价格怎么看、要去哪里买

- 页面上那个价是**国内含税挂牌价的参考值**，每条都带采集日期；活动价会标「可能随活动变化」。
- **本站不给购买链接，也不代理销售**，所以没有「立即购买」按钮。要买就按型号名 + 立创编号（如 XT30 的 `C99102`）去立创商城或厂商代理问；
  加工件去[采购库](/suppliers.html)，按质量、交期、能不能开票筛。
- 比价前先看清一件事：**¥499 的大疆 M3508 是「电机 + 减速箱」，不含驱动器**，得另配 C620 电调；
  集成驱动的关节模组才是「插上就能转」。拿两者直接比价是不公平的。

## 四个新人最常踩的坑

1. **把峰值当连续用**：峰值受绕组热容限制，是时间的函数 —— 没写持续时间和初始温度的峰值，别当额定值算。
2. **把「生态 ×N」当 star 数**：N 是官方项目、仿真、训练、部署、导航、控制各环节公开仓库的数量，衡量「能借多少现成工程」。
3. **看到「暂无评分」以为评价差**：现在 **351 个部件大多还没有人打分**，那不是加载失败，是还没人写第一条。
   「实际使用」下面就能写，第一条可以是你。
4. **拿没核对过的数字做热设计**：商品页参数、转述数据都可能过期；扭矩、电流、精度回原厂页面复核一遍。

## 剩下这些是给维护者看的

页面和文章里会出现 `tau_basis`、`driver_integrated`、`part_edits`、`own_hardware_avg` 这种带下划线的名字 —— 那是数据字段名。
读不懂**可以跳过**，页面上对应的中文标签才是给读者的（「扭矩口径」「内置驱动」「修改记录」）。

## 这个站怎么用（细则）

上面那条路线走完，再回来看这一节就够了：它讲的是「哪个数字能信、为什么有的格子是「—」、我想做 XX 该去哪一页」。
看完你应该知道哪些数字可以直接拿去算。

### 一、先认识这里的六类内容

| 板块 | 回答什么问题 | 什么时候去 |
|---|---|---|
| **选型台（试验版）** | 「按我的构型和功能，该配哪些件、多少数量」 | 还没定 BOM，或想核对一套配置；结果用于起步，最终以部件库参数为准 |
| **部件库** | 「这个关节电机 / 芯片 / 传感器，参数到底是多少，多少钱，谁用过」 | 你在选型、做 BOM、或者想核对某个数 |
| **方案库 · 整机** | 「这台机器是什么方案，开源世界里有谁在它上面做过事」 | 你在定方案、找参考实现、评估「能不能照着做」 |
| **设备库** | 「做这台机器要买哪些工具与仪器」 | 准备开工、补工具 |
| **采购库** | 「加工和元件去哪买，哪家有坑」 | 要下单、比价、找打样 |
| **软件库** | 「仿真、训练、部署这条链上，每一层该用哪个工具，许可能不能商用」 | 你要搭环境、换后端、或者判断某个框架能不能进产品 |

六个入口是**并列**的，不是目录关系：选型台只做推导、不存数据；部件库不包含整机；整机里也不重复部件的参数。

### 二、部件页：先看来源和核对日期

每个部件页左边是参数，右边是「实际使用」。每个数字都尽量标出来源，页面上也会写最近核对日期：

| 你看到的 | 含义 | 你该怎么用 |
|---|---|---|
| **有来源、有核对日期** | 能指回厂商手册、官方数据表或商品页，并记录了最近核对时间 | 可以直接拿去做计算；商品页来源的关键数字（扭矩、电流、精度）仍建议回原厂复核 |
| **只有转述 / 没写出处** | 暂时没找到一手来源，或只有二手描述 | 只当线索，别引用数值，更别拿去做热设计 |

没有出处不等于「这项没有」：厂商没公布、我们没核到，都写 `null`。

#### 为什么很多格子写着「—」

因为厂商没公布，或者公布了但我们没核到。这里的规则是**缺就写 `null`，不省略字段**：

- 省略字段会让人以为「这项没有」
- 而 `null` 明确表示「厂商没公布」

所以你看到「—」有两个可能：厂商没给，或者我们还没核到。**没有第三种可能**（比如「约」「大概」这种糊过去的写法 —— 这里不用）。

#### 几个容易踩的口径

| 你会遇到的坑 | 这里的处理 |
|---|---|
| 扭矩是电机端还是减速箱输出端？ | **一律给输出端**（含减速箱）。原始值留在 `specs.torque_raw` |
| 峰值扭矩能连续跑吗？ | 不能。峰值有持续时间与初始温度条件，页面会写 |
| 额定电压还是范围？ | 分开两个字段，不合并 |
| 价格含不含税、是不是活动价？ | 只收国内含税挂牌价，来源与采集日期写进备注；活动价标注「可能随活动变化」 |

### 三、评分怎么读（以及为什么样本少时会直说）

每条评价**必填三项**：总分（1–5）、你用过这个件吗、一句话理由。分维度（性价比 / 做工 / 文档 / 参数可信度…）是选填，按品类不同。

三条规则值得知道：

1. **一人一件一票**：唯一键是「你的账号 + 部件 id」。改主意就编辑原来那条 issue，不会算两票。
2. **样本 < 3 条标「样本不足」**：1 条 5 分和 20 条 5 分不是一个确定程度，页面不把它们当一回事。
3. **装过机和没装过机分开算**：只有「装过机」的评价进装过机均分。

评分不是「谁更专业」加权 —— 那会变成黑箱。只用「装过 / 没装过」这个可核对的区分。

> 说明：**现在大多数部件还是「暂无评分」**，评分区是空的而不是显示 0 分。规则先写在这里，等你来写第一条。

### 四、列表页怎么筛

三个列表页共用一套交互：

- **搜索框**：型号、厂商、类型都能搜（顶部导航的搜索框也能搜到具体型号页）
- **分面（chips）**：点一下筛，再点一下取消。部件页按品类分面，整机页按构型 + **有无开源生态**，软件页按层
- **排序**：右上角下拉。部件可以按任意参数列排；整机有「按开源生态」；软件有「按许可宽松度」

两个新人常卡住的地方，先记住：

- 顶部那个 **「★ 精选」** 目前是**默认全收录**，所以它显示的数量就是全库数量，不是「精挑过的 300 个」；关掉它结果不会变多。
- 搜出「0 件 / 没有符合条件的部件」时，多半是搜索词还在生效：**先清空搜索框**，再点品类。

### 五、整机页：为什么强调「开源生态」

一台机器的参数表只能告诉你它多大、多重、几自由度。但真正决定「我能不能做出来」的是：

**这台机器在开源世界里有多少现成工程可以借。**

所以整机页每张卡片都有一行「开源生态 N 项」，点进详情页会按环节拆开：

```
官方项目 · 官方描述/资产 · 官方 SDK · 仿真 · 训练 · 部署 · 导航 · 控制/MPC · 工具/资料
```

**只列有公开 GitHub 仓库的项目** —— 本地工程和「通用 API 参考」不上页面，因为读者点不动，
也说明不了这台机器。42 台全部标了生态数，并且至少给了一个公开仓库链接；没有的就写「—」，不凑数。

### 六、软件页：许可和版本比功能重要

选软件时最容易踩的不是「功能不够」，而是：

- **许可不能商用**（GPL 进产品要开源）
- **版本对不上文档**（教程写 2.x，你装的是 1.x）
- **硬件门槛**（Isaac 系要 NVIDIA 卡，MuJoCo 单机 CPU 就行）

所以每张卡片上**许可、版本、语言**都直接标出来，还写了一句「什么时候用」：

- 宽松（Apache / MIT / BSD）→ 品牌色
- copyleft（GPL / MPL）→ 琥珀色
- **未核对 → 虚线灰**，因为「读不到」和「没有」是两件事，我们不猜

### 七、这些数据是谁核的、错了找谁

- 每个部件页底部写着**来源、收录方式、核对日期**
- **贡献者页**写清每个人具体做了什么（不从 git log 生成 —— 机器只会数 commit，说不出谁核过哪本手册）
- 发现错误：不熟悉 git 的走[投稿页](/submit.html)的「纠参数 / 补数据」，填个表单就行（约 2 分钟）；
  会改 JSON 的，部件页底部有「在 GitHub 上编辑这条数据」直达那个文件

数据出错时，我们希望能找到具体的人，而不是一句「欢迎指正」。
